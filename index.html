02 / RELATIONAL SELECTOR未检测

子元素变了，父元素知道。

:has() 让外层卡片直接响应内部复选框的状态，不需要事件监听器。

试一试 → 点击卡片，或用 Tab 聚焦后按空格。

分工：HTML 提供可操作的复选框，CSS 响应选中状态；没有保存数据。

03 / CONTAINER SIZE未检测

看容器脸色，不看屏幕大小。

浏览器窗口不动。只改变组件可用的空间，内部就能从纵向排列切换为横向排列。

山野来信

同一个组件，在侧栏和主栏里各得其所。

试一试 → 拖动滑块。容器超过 340px 时改为两列；窄屏可能始终为一列。

分工：JS 只改变容器宽度；决定布局的条件写在 CSS 中。

查看关键 CSS ↗
.resizable { container: card / inline-size; }
.responsive-card { display: grid; }
@container card (min-width: 340px) {
  .responsive-card {
    grid-template-columns: 105px 1fr;
  }
}

04 / SCROLL-DRIVEN ANIMATION未检测

滚动条，就是动画时间轴。

这里没有 scroll 监听器。绿色进度条的动画进度直接绑定到阅读区的滚动位置。

01 — 时间不再是唯一的刻度。
把鼠标移进这里，向下滚动。也可以聚焦后使用方向键。

02 — 停下来，动画也停下。
普通动画随时间变化；滚动动画随滚动位置变化。

03 — 往回滚，也能倒着播放。
无需计算百分比，也无需逐帧修改宽度。

04 — 抵达终点。
这也是阅读进度、横向展览和滚动叙事的基础。

试一试 → 滚动这张卡片里的阅读区，观察顶部绿线。

边界：呈现滚动进度不等于业务上已读，也不会保存阅读记录。

查看关键 CSS ↗
.read-progress {
  transform-origin: left;
  animation: read-progress linear both;
  animation-timeline: scroll(nearest block);
}
@keyframes read-progress {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }

06 / ANCHOR POSITIONING未检测

气泡自己找位置，还会避让。

气泡引用命名锚点。上方空间不足时，浏览器尝试把它放到下方；锚定查询再调整箭头与颜色。

参照物
我跟随锚点，不计算坐标。

试一试 → 将滑块移到最左。锚定查询支持待检测。

分工：JS 只移动参照物。定位、避让、翻转后的样式都由 CSS 负责。

查看关键 CSS ↗
.anchor-target { anchor-name: --demo-anchor; }
.anchor-tip {
  position: absolute;
  position-anchor: --demo-anchor;
  position-area: top;
  position-try-fallbacks: bottom;
  container-type: anchored;
}
@container anchored(fallback: bottom) {
  .tip-inner { background: #e1d8f4; }
  /* 同时将箭头移到气泡上方 */
}

我有了入场的起点。

一个变量，就能切换一套表现。

同一个组件，不同的性格。

11 / TYPED ATTRIBUTE未检测

HTML 属性，直接成为样式值。

高级 attr() 能把属性解析成百分比或颜色。三条数据共用同一条规则，长度与颜色直接读取属性。

92% / 探索
68% / 理解
45% / 实践

观察 → 这不是三套宽度类名。可在开发者工具里修改 data-value（如 75%）。

边界：CSS 读取已有属性，不获取远程数据。浏览器不支持时显示等长灰条。

查看关键 HTML / CSS ↗
<div class="attr-bar"
  data-value="92%" data-color="#31583c">92%</div>

.attr-bar {
  width: attr(data-value type(<percentage>), 50%);
  background: attr(data-color type(<color>), #31583c);
}

12 / COLOR SCHEME未检测

一行颜色，明暗两种答案。

light-dark() 根据生效的 color-scheme 选取颜色，也能跟随系统偏好。

内容与结构相同。背景、文字和原生控件一起适应明暗环境。

试一试 → 切换卡片主题。只影响本示例，方便同时比较其他实验。

分工：复选框驱动 color-scheme；light-dark() 选择颜色值，不负责保存偏好。

查看关键 CSS ↗
.color-demo {
  color-scheme: light;
  background: light-dark(#fffefa, #263327);
  color: light-dark(#263327, #e5efd8);
}
.color-demo:has(input:checked) {
  color-scheme: dark;
}
/* 跟随系统：color-scheme: light dark; */

KNOW THE BOUNDARY

厉害，但不是万能。

HTML：按钮、表单、标题、内容与原生交互。CSS：布局、视觉、状态响应与环境适配。JavaScript：业务规则、网络请求、数据处理和持久化。这是实用的职责划分，不是三门技术绝对互斥。

两处值得修正：CSS 不能给元素设置 role；应使用原生语义元素，必要时通过 HTML 属性或 JS 设置 ARIA。伪元素生成内容也并非一定不进入可访问性树，各浏览器与辅助技术行为可能不同，关键文案应保留在 HTML 中。

视觉顺序不等于阅读与焦点顺序。CSS 不会像 DOM API 一样增删真实节点，但 display: none 等样式会影响可访问性树，不能把「语义完全不受 CSS 影响」当作规则。
